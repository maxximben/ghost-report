# Как писать содержание отчёта

Оформление берёт на себя генератор, тебе остаётся содержание. Пиши от лица автора работы (безличные формы: «были рассмотрены», «реализован», «получено»), научно-деловым стилем, без разговорных оборотов и без воды. Опирайся только на реальный материал: задание, код, результаты запуска, измерения.

## Общий скелет

| Элемент | ЛР | ДЗ | РГР | Практика |
|---|---|---|---|---|
| Реферат | – | рекомендуется | да | да |
| Содержание | рекомендуется | да | да | да |
| Введение | да | да | да | да |
| Основная часть | 1–2 раздела | по задачам | 2–3 раздела | по этапам практики |
| Заключение | да | да | да | да |
| Список источников | да | да | да | да |
| Приложения | листинг (обязательное) | при необходимости | листинг, данные | дневник, материалы |

Объём ориентировочный; если в задании указан другой – следуй заданию.

## Введение (~2 стр.)

1. Актуальность проблемы (2–4 абзаца): где встречается задача, почему важна, какие есть подходы (со ссылками `[@id]`).
2. Предмет работы одной-двумя фразами.
3. **Цель** одним предложением: «Целью данной работы является …».
4. **Задачи** списком: «Для достижения цели были поставлены следующие задачи:» и перечень с «–» (глаголы неопределённой формы: изучить, разработать, реализовать, провести).

Каждая задача = раздел (или подраздел) основной части. Заключение потом отвечает на те же пункты.

## Основная часть

Структурируй по перечню задач. Типовые разделы:

- **Теоретическая часть**: постановка задачи, определения, математическая модель, формулы (нумеруемые), алгоритм; со ссылками на источники. Каждую формулу вводи фразой («…рассчитывается по формуле:»), после формулы – «где …» с расшифровкой обозначений.
- **Практическая часть / реализация**: средства (язык, библиотеки), описание алгоритма, фрагменты кода (вводная фраза → блок кода → пояснение), полный листинг – в приложение.
- **Результаты / эксперименты**: исходные данные, таблицы, графики, анализ. Каждую таблицу и рисунок сначала упомяни в тексте (`в таблице [[tab-…]] приведены…`, `на рисунке [[fig-…]] показано…`), потом вставь, потом прокомментируй вывод.
- **Обсуждение / сравнение** (РГР): сопоставь с теорией и с другими подходами.

Для ЛР достаточно: цель и задание → теоретические сведения → ход выполнения (код, скриншоты, результаты) → выводы (в заключении).

Рисунки и таблицы не должны висеть без пояснений. Скриншоты – только осмысленные (результат запуска, интерфейс, график), с названием «Результат работы программы для …».

## Заключение (0,5–1 стр.)

- Одним-двумя предложениями: что сделано.
- По каждой задаче из введения: что получено (с конкретными числами и результатами, но без повторения всего текста).
- Выводы о достижении цели.
- В конце – точки развития («Дальнейшим развитием работы может стать …»).

## Реферат (РГР, ДЗ, практика)

```
# Реферат

Объектом исследования является …

Предметом исследования является …

Цель работы – …

В процессе выполнения были рассмотрены …, предложен …, изучены ….

В результате был реализован / получен ….
```
Строку «Отчет N с., N рис., …» и ключевые слова генератор добавит сам (`keywords:` в front matter, 5–10 слов).

## Приложения

- Листинг программы – `# Приложение [обязательное]: Листинг программы {#app-code}` + блок кода; ссылайся на него в тексте: «полный листинг приведён в приложении [[app-code]]».
- Справочные материалы (таблицы данных, длинные графики) – `[справочное]` или без пометки (выберется автоматически).

## Список источников

Минимум: 3–5 для ЛР, 5–10 для РГР (если не сказано иное). Ссылки в тексте `[@id]` – все источники должны быть процитированы. Описание – из `sources.json` (см. `sources-format.md`). Электронные ресурсы – не более трети.

## Антигаллюцинации (важно)

- Не придумывай источники, авторов, страницы, ISBN, DOI, даты обращения.
- Не придумывай численные результаты: запусти код / используй данные пользователя. Если запуск невозможен – скажи об этом и пометь, чего не хватает.
- Не вставляй «заглушки» («рисунок будет позже», «число, месяц, год»): проверка пометит их ошибкой.
- Если задание неполное – задай пользователю один сжатый вопрос со всеми недостающими данными, а не угадывай.
